# 포르투나볼 AI (FortunaBall AI)

> 로또 6/45의 **역대 당첨 데이터를 통계로 분석**하고, 그 통계로 **번호를 만들어 주고**, AI가 **쉽게 설명해 주는** 웹 서비스입니다.

- 번호는 **서버의 통계 알고리즘**이 만들고, AI는 그 결과를 **설명**하는 역할만 합니다.
- 모든 결과는 **참고용**입니다. 당첨을 보장하지 않습니다.
- 회원가입 없이 쓸 수 있고(이 기기에서 발급한 내역은 기기 안에서 구분), 운영자는 별도 **관리자 사이트**로 관리합니다.

---

## 1. 이 서비스로 할 수 있는 일

| 구분 | 기능 | 한 줄 설명 |
|---|---|---|
| 번호 만들기 | **통계 번호 생성** | 대상 회차를 고르고 게임 수를 정하면 통계 기준에 맞는 번호를 만들어 줘요. |
| | **패턴 모아보기** | 홀짝·고저·구간 같은 패턴을 비교해 보고 골라서 생성해요. |
| | **AI 애널리스트** | 대화로 번호를 분석하고 질문해요. (대화 내용은 서버에 저장하지 않아요) |
| | **AI 꿈풀이** | 꿈 내용을 풀이하고 참고 번호를 만들어 줘요. |
| 당첨 정보 | **회차별 당첨번호** | 1회부터 최신 회차까지 당첨번호·당첨금·당첨자 수를 봐요. |
| | **통계 분석** | 많이 나온 번호, 구간 분포, 지역별 통계 등을 한눈에 봐요. |
| | **우리 서비스 당첨 기록** | 이 서비스에서 발급한 번호로 당첨된 기록을 공개해요. |
| | **명당 지도** | 1·2등 배출 판매점을 지도와 목록으로 찾아요. |
| 내 번호 | **발급 내역 조회** | 번호를 확정하면 발급코드가 생기고, 코드로 내역을 다시 볼 수 있어요. |
| | **당첨 확인** | 발급 번호를 실제 당첨번호와 비교해요. 로또 용지 QR로도 확인해요. |
| | **당첨 인증 등록** | 당첨된 용지 사진을 익명으로 올려 인증해요. (관리자가 검수) |
| 계산 · 가이드 | **당첨금 · 세금 · 실수령액** | 회차와 등수를 고르면 세금을 뗀 예상 수령액을 계산해요. |
| | **당첨금 수령 가이드 / 서비스 안내** | 당첨금 받는 방법과 이용 전 유의사항을 안내해요. |
| 기타 | **공지사항, 공유하기, 좋아요** | 새 소식 확인, 링크 공유(Web Share API), 페이지 좋아요 |

## 2. 사용 방법 (사용자 화면)

### 번호를 만들어 발급받기
1. 홈 또는 메뉴의 **통계 번호 생성**으로 들어가요.
2. 대상 회차(가장 가까운 추첨 회차가 기본)와 게임 수를 고르고 **생성**을 눌러요.
3. 결과 화면에서 번호와 통계 설명을 확인해요. 마음에 안 들면 **다시 생성**할 수 있어요.
4. 마음에 드는 결과를 **발급 확정**하면 **발급코드**가 생겨요. 코드를 적어 두면 나중에 조회할 수 있어요.
   - 생성만 하고 확정하지 않은 결과는 **30분 뒤 사라지고** 기록으로 남지 않아요.
   - 같은 회차에서 같은 번호 조합은 **최대 3번**까지만 발급돼요.

### 발급한 번호가 당첨됐는지 확인하기
- **발급 내역 조회**에서 이 기기의 발급 내역을 보거나 발급코드를 입력해요.
- 추첨이 끝나면 당첨 결과(등수)가 자동으로 표시돼요.
- 로또 용지가 있으면 **회차별 당첨번호** 화면의 용지 확인에서 **QR을 촬영**하면 바로 결과가 나와요.

### AI 기능 쓰기
- **AI 애널리스트**: "최근 많이 나온 번호는?" 같은 질문을 하면 통계를 근거로 답해요. 지도 화면에서는 "근처 명당"도 물어볼 수 있어요.
- **AI 꿈풀이**: 꿈을 적으면 풀이와 참고 번호를 알려 줘요. 이어서 질문하면 앞의 대화 흐름을 기억하고 답해요.
- 비용 보호를 위해 **하루 사용 횟수에 한도**가 있어요. (비회원 1명 하루 5회, 접속지 1곳 하루 10회, 서비스 전체 하루 300회 / 월 예산 상한)
  한도를 넘으면 AI 기능만 잠시 멈추고, 나머지 기능은 그대로 써요.
- "무조건 1등 번호 줘" 같은 **당첨 보장 요구**나 로또와 관계없는 질문은 AI를 부르지 않고 안내 문구로 답해요.

### 명당 지도
- 판매점을 목록과 지도로 보고, 당첨 횟수·1등/2등 이력을 확인해요.
- **내 위치 기준 검색**은 스위치를 켜고 동의하면 쓸 수 있어요. 위치는 **저장하지 않고, 로그에 남기지 않고, AI에도 보내지 않아요.**

### 당첨금 계산
- **당첨금 · 세금 · 실수령액**에서 회차와 등수를 고르면 서버가 세금을 계산해 줘요. (참고용)

## 3. 관리자 화면 (`/admin`)

운영자 전용 영역으로, 일반 화면과 분리돼 있어요. 첫 관리자 계정은 `.env`의 값으로 만들어져요.

| 메뉴 | 하는 일 |
|---|---|
| 대시보드 | 오늘의 발급·AI 사용·오류 현황 한눈에 보기 |
| 회차 | 공식 사이트에서 회차 데이터 **재수집** (숫자를 직접 고치지 않아요) |
| 발급 내역 / 당첨 검증 | 발급 기록 조회, 당첨 결과 검증 실행 |
| 당첨 기록 / 인증 사진 | 사용자가 올린 당첨 인증을 검수하고 승인·반려 |
| 판매점 | 판매점 CSV 업로드와 관리 |
| AI 사용 / 꿈 데이터 | AI 사용량·실패 로그, 꿈 상징 데이터 관리 |
| 콘텐츠 / 공지 | 안내문·공지사항 편집 |
| 시스템 / 정책 | 스케줄러 실행 상태, AI 입력 예외 정책(차단 키워드 등) |

로그인은 **세션 방식**이에요. 비밀번호는 BCrypt 해시로만 저장하고, 같은 접속지에서 5번 틀리면 15분 동안 로그인을 막아요.

## 6. 실행 방법

### 준비물
Java 21, Node.js(LTS), MySQL 8.0, Git

### 1) 코드 받기
```bash
git clone https://github.com/seun6h0925-rgb/fortunaball-ai.git
cd fortunaball-ai
```

### 2) 환경변수 파일 만들기
저장소 맨 위 폴더에서 `.env.example`을 복사해 `.env`로 만들고 값을 채워요. (`.env`는 Git에 올라가지 않아요)

```properties
DB_HOST=localhost
DB_PORT=3306
DB_NAME=fortuna_ball
DB_USER=fortuna
DB_PASSWORD=내가_정한_비밀번호

AI_API_KEY=            # 비워 두면 AI 기능만 "이용 불가"로 표시되고 나머지는 정상 동작해요
ADMIN_LOGIN_ID=        # 첫 관리자 아이디
ADMIN_INITIAL_PASSWORD=  # 첫 관리자 비밀번호 (8자 이상)
UPLOAD_DIR=            # 당첨 인증 사진을 저장할 폴더 (프로젝트 밖 절대 경로, 경로에는 \ 대신 / 사용)
```

### 3) DB 만들기 (처음 한 번만)
MySQL에서 아래 순서로 SQL 파일을 실행해요. (`docs/db/`)

1. DB와 사용자 만들기 — `schema.sql` 맨 위 주석의 `CREATE USER`, `CREATE DATABASE`, `GRANT` 문
2. `schema.sql` — 테이블 생성
3. `alter_2026-10-21_store.sql` — 판매점 관련 컬럼 추가
4. 시드 데이터: `seed_dream_symbols.sql`, `seed_dream_symbols_2.sql`, `seed_dream_symbols_3_korean.sql`(꿈 상징), `seed_ai_policy.sql`(AI 입력 정책), `seed_content_pages.sql`(안내 문구)

> 이미 실행한 파일은 다시 실행하지 마세요. 자세한 화면 안내(IntelliJ 기준)는 `docs/setup/NEW_PC_SETUP.md`에 있어요.

### 4) 백엔드 실행
```bash
cd backend
./gradlew bootRun        # Windows PowerShell: .\gradlew bootRun
```
- 브라우저에서 `http://localhost:8080/api/health` 를 열어 `success: true`가 나오면 서버가 정상이에요.
- 서버를 켜면 빠진 회차를 **공식 사이트에서 자동으로 수집**해요. 처음 켤 때는 1회부터 최신 회차까지 채우느라 **몇 분** 걸려요. (그동안에도 서버는 정상 응답해요)

### 5) 프론트엔드 실행
```bash
cd frontend
npm install
npm run dev
```
- `http://localhost:5173` 에서 화면을 열어요.
- 화면의 `/api` 요청은 개발 서버가 백엔드(8080)로 대신 전달해서, 별도의 CORS 설정 없이 로그인 쿠키도 그대로 동작해요.
- 관리자 화면은 `http://localhost:5173/admin` 이에요.

### 6) 판매점 데이터 넣기 (명당 지도용, 선택)
`docs/db/winning_stores_262_1246.csv`가 판매점·당첨 이력 데이터예요. 서버를 켤 때 `--fortuna.store.import.path=<CSV 경로>` 옵션을 한 번 주면 가져와요. 관리자 화면의 **판매점** 메뉴에서 CSV를 올려도 돼요.

### 테스트
```bash
cd backend
./gradlew test
```
번호 생성 규칙, 통계 계산, 당첨 검증, AI 한도·정책, 관리자 권한, 예외 응답 등을 테스트 코드로 확인해요.

## 7. 자동으로 돌아가는 작업

| 작업 | 시각 (한국 시간) | 내용 |
|---|---|---|
| 새 회차 수집 | 토 20:45 → 21:00~23:45 15분마다, 일 12:00(보강) | 공식 사이트에서 최신 당첨 결과를 가져와요 |
| 시작 수집 | 서버 켤 때 | 처음에는 1회부터 전체를, 이후에는 놓친 회차만 채워요 |
| 통계 갱신 | 토 20:00 및 서버 시작 시 | 통계 분석용 집계(스냅샷)를 새로 만들어요 |
| 좋아요 기록 정리 | 매일 00:10 | 오래된 하루 단위 좋아요 기록을 지워요 |

같은 회차를 여러 번 수집해도 **중복 저장되지 않고**, 수집이 이미 돌고 있으면 건너뛰어요. 실행 결과와 실패는 로그 테이블(`scheduler_log`, `api_error_log`)에 남아요.

## 8. 핵심 설계 원칙

**번호 생성**
- 번호는 서버의 통계 알고리즘만 만들어요. AI는 번호를 직접 만들지 않고 설명만 해요.
- 후보 조합의 홀짝·고저·합계·구간·출현 빈도를 점수로 매기고, 한쪽으로 지나치게 몰린 조합은 걸러요.
- 생성 결과는 30분만 임시 보관(Caffeine 캐시)하고, **사용자가 발급을 확정했을 때만 DB에 저장**해요.

**데이터**
- 회차·당첨번호는 공식 출처 데이터만 써요. 관리자도 숫자를 직접 고치지 않고 **재수집**으로만 바로잡아요.
- DB 테이블은 `schema.sql`로만 만들어요. (`ddl-auto: none`, 자동 생성·변경 금지)

**AI 안전장치**
- 모든 AI 호출은 한 관문(`AiGateway`)을 지나요. 하루 횟수·월 비용·분당 횟수를 확인하고, 실패하면 사용 횟수를 되돌려 줘요.
- 대화 내용은 서버에 저장하지 않아요. 이어지는 대화는 화면이 최근 대화 몇 개만 함께 보내서 맥락을 유지해요.
- AI 응답 시간은 20초로 제한하고, 넘으면 실패로 처리해 재시도를 안내해요.

**오류 추적**
- 모든 응답은 같은 형식을 써요. 성공 `{success, data, message}`, 실패 `{success, errorCode, message, traceId}`.
- 요청마다 `traceId`를 붙여 로그(`logs/app.log`, `logs/error.log`)에서 한 요청의 흐름을 따라갈 수 있어요.

**보안 · 개인정보**
- API 키·DB 비밀번호는 `.env`에만 있고 Git에 올리지 않아요.
- 관리자 API는 로그인한 관리자만 호출할 수 있고, 로그인 쿠키는 `HttpOnly`·`SameSite=Lax`예요.
- 발급코드 조회, 당첨 인증 등록 같은 곳에는 접속지(IP)별 **분당 횟수 제한**이 있어요.
- 업로드 사진은 확장자·형식·용량을 서버에서 검사하고, 프로젝트 밖 비공개 폴더에 저장해요.
- 위치 정보는 저장·로그·AI 전송을 하지 않아요.

## 10. 개발 방식

- 백엔드와 DB를 먼저 만들고, 그 위에 화면을 연결했어요.
- **기능 하나에 브랜치 하나**(`feature/…`)로 작업하고, 기능이 끝나면 커밋한 뒤 `--no-ff`로 `main`에 합쳤어요.
- 커밋 메시지는 `feat(범위): 내용` 형식을 써요.
- 설계서의 용어·테이블명·API 경로를 바꿀 때는 문서와 코드를 함께 고쳐요.
- 헷갈리기 쉬운 처리는 코드 위에 주석으로 이유를 적어 두었어요.

# 포르투나볼 AI

번호 생성은 AI가 만든 계산식에 통계 데이터를 얹어 로또 정보·번호 생성하는 서비스입니다. 

모든 결과는 당첨을 보장하지 않으며, 사용자가 통계와 분석 정보를 참고할 수 있도록 제공됩니다.

## 주요 기능

- 통계 기반 로또 번호 생성
- AI 로또 애널리스트
- AI 꿈풀이 및 참고 번호 제안
- 회차별 당첨번호 조회
- 역대 당첨번호 통계 분석
- 번호 발급코드 생성 및 발급 내역 조회
- 발급번호와 실제 당첨번호 비교
- 우리 서비스 당첨 기록 관리
- 로또 명당 및 판매점 지도
- 당첨금·세금·실수령액 계산
- 당첨금 수령 가이드
- 서비스 안내 및 유의사항
- 관리자 페이지

## 백엔드 구성

백엔드는 Controller, Service, Repository, Entity 구조로 나눕니다.

- Controller: 클라이언트 요청과 응답 처리
- Service: 번호 생성, 통계 계산, 검증 등 비즈니스 로직 처리
- Repository: JPA를 이용한 DB 조회·저장
- Entity: DB 테이블과 연결되는 객체
- Scheduler: 공식 데이터 자동 수집
- Cache: 임시 결과와 통계 결과 임시 보관

## 데이터 처리 원칙

- 회차와 당첨번호는 공식 출처의 데이터만 사용합니다.
- 공식 데이터는 회차 중복 여부를 확인한 뒤 저장합니다.
- 같은 데이터를 여러 번 수집해도 중복 저장되지 않도록 처리합니다.
- 판매점 정보와 당첨 이력은 출처와 수집일을 관리합니다.
- 꿈 상징 데이터는 출처를 확인하고 직접 재작성한 참고 자료를 사용합니다.
- 데이터 수집 실패와 처리 결과는 로그로 남깁니다.

## 번호 생성 원칙

- 번호 조합은 서버의 통계 알고리즘으로 생성합니다.
- AI는 번호를 직접 생성하거나 당첨 가능성을 보장하지 않습니다.
- 후보 조합의 홀짝, 고저, 합계, 구간, 출현 빈도 등을 분석합니다.
- 특정 번호나 구간에 지나치게 몰린 조합은 검증 과정에서 제외할 수 있습니다.
- 생성 결과는 임시 보관 후 사용자가 발급을 확정했을 때만 DB에 저장합니다.
- 재생성하거나 만료된 결과는 발급 기록으로 저장하지 않습니다.

## 자동 업데이트와 캐시

- 스케줄러가 정해진 시간에 공식 회차 데이터를 확인합니다.
- 서버 시작 시 최신 회차 데이터도 확인합니다.
- 동일한 작업이 반복되어도 데이터가 중복되지 않도록 처리합니다.
- 동시에 여러 수집 작업이 실행되지 않도록 잠금 처리합니다.
- 통계 조회 결과와 번호 생성 임시 결과에는 캐시를 사용할 수 있습니다.
- 캐시가 만료된 결과는 다시 계산하거나 새로 생성합니다.

## 관리자 기능

관리자 페이지는 일반 사용자 화면과 분리된 운영 영역입니다.

- 관리자 로그인 및 권한 확인
- 회차 데이터 재수집
- 번호 발급 기록 조회
- 당첨 결과 검증
- 익명 당첨 인증 검수
- 판매점 데이터 관리
- 꿈 상징 데이터 관리
- 공지사항 및 안내문 관리
- AI 사용량과 API 실패 로그 확인
- 스케줄러 실행 상태 확인

공식 회차 데이터는 원칙적으로 관리자가 숫자를 직접 수정하지 않고 공식 출처에서 재수집합니다.

## 보안 원칙

- API 키, DB 비밀번호, JWT 비밀키는 환경변수로 관리합니다.
- `.env` 파일은 Git에 커밋하지 않습니다.
- 관리자 API는 관리자 권한을 확인한 뒤 실행합니다.
- 발급코드는 추측하기 어렵게 생성하고 조회 횟수를 제한합니다.
- 업로드 파일은 확장자, MIME 타입, 용량을 검증합니다.
- 관리자 비밀번호는 BCrypt 방식으로 저장합니다.
- 사용자 입력과 AI 요청 내용은 서버에서 검증합니다.

## 실행 준비

필수 설치 프로그램은 Java 21, Node.js, MySQL 8.0, Git입니다.

실행 전 `.env.example`을 참고해 `.env` 파일을 만들고 DB 연결 정보와 필요한 API 키를 입력합니다.

MySQL에 DB를 생성한 뒤 DB 설계서에 있는 스키마 파일을 먼저 실행합니다.

백엔드를 실행한 후 프론트를 실행하고, 프론트에서 백엔드 API가 정상적으로 연결되는지 확인합니다.

## 개발 원칙

- 백엔드와 DB 처리를 먼저 구현한 뒤 프론트를 연결합니다.
- 한 번에 하나의 기능을 구현하고 테스트합니다.
- 기존 설계서의 용어, 테이블명, API 경로를 임의로 변경하지 않습니다.
- 설계 변경이 필요한 경우 관련 문서와 코드를 함께 수정합니다.
- 중요한 처리와 예외 기준은 코드에 주석으로 남깁니다.
- 최종 배포 가능한 서비스 완성본을 목표로 개발합니다.

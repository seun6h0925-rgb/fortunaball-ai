| --- | --- | --- | --- | --- | --- |

| API-02 | GET | `/api/draws/{round}` | 회차별 당첨번호 조회 | 회차 번호 | 당첨번호, 보너스번호, 등수별(1~5등) 당첨금, 당첨자 수 |

| API-04 | POST | `/api/issues` | 발급 확정 (발급코드 생성 및 발급 이력 저장) | 임시 확정 토큰, 게스트 식별값 (번호와 회차는 받지 않고 서버가 임시 결과와 대상 회차를 재검증) | 발급코드, 발급시간, 대상 회차, 발급번호, 교체된 게임 정보(같은 조합이 이미 3회 발급된 게임만 다른 번호로 교체하며 게임 번호와 변경 전·후 번호 포함, 없으면 빈 목록) |

| API-06 | GET | `/api/issues/{issueCode}/result` | 발급번호 당첨 검증 결과 조회 (조회 횟수 제한) | 발급코드 | 일치 개수, 보너스 일치 여부, 당첨 등수 |
| API-07 | POST | `/api/ai/analyst` | AI 로또 애널리스트 | 질문(`question`), 이전 대화(`history`, 역할·내용 배열, 화면은 최근 6턴만 전송), 번호, 발급코드, 위도·경도(지도 AI에서 위치 스위치가 켜진 경우에만, 저장·로그·AI 전달 없음) (번호 생성 요청이면 서버가 질문에서 게임 수·포함·제외 번호를 추출) | 질문 유형(`questionType`), 정책 코드(`policyCode`, 고정 응답일 때. 위치 꺼짐 시 LOCATION_REQUIRED), 안내 문구(`message`), 분석 답변(`answer`, 500자 이내, 한 번에 응답), 생성 번호(`generated`, 번호 생성 요청일 때: 임시 확정 토큰·게임 번호), 분석 근거(`evidence`: 기준 설명 `basis`, 항목 `items[{label,value}]`, "통계 근거 보기"용), 참고 데이터(`references`), 유의 문구(`notice`), 오늘 남은 횟수(`remainingToday`), 대화 기록 문구(`historyText`), 추천 질문(`suggestions`), 화면 동작(`action`, 사용법 안내가 필요하면 OPEN_GUIDE), 횟수 차감 여부(`charged`) |
| API-08 | POST | `/api/ai/dream` | AI 로또 꿈풀이 (여러 번 주고받는 대화형. 처음에는 꿈 내용만 보내고, 이후에는 직전 응답의 단계·유지 번호·게임 수·확정 토큰을 그대로 되돌려 보낸다) | 꿈 내용(`dream`, 5~300자), 사용자 답변(`reply`), 단계(`step`), 유지할 번호(`keep`), 게임 수(`gameCount`), 확정 토큰(`confirmToken`) | 매칭 결과(`matchResult`: FULL_MATCH, PARTIAL_MATCH, NO_MATCH), 단계(`step`: TALK, NEED_MORE, ASK_STAT_NUMBERS, ASK_FILL, ASK_OVERFLOW, CONFIRM, CONFIRMED), 정책 코드, 안내 문구(`message`), 되묻는 말(`question`), 꿈 상징(`symbols`: 키워드와 해석 목록. 해석마다 상황·요약·긍정/부정·한국 전통/해외 전통 구분), 해석 결과(`interpretation`), 번호(`numbers`: 번호와 출처 DREAM_TEXT·SMORFIA·CHARADA·SERVICE·STAT), 게임 번호(`games`), 유지 번호, 게임 수, 확정 토큰·유효 시간(`tokenTtlMinutes`), 대상 회차, 화면 동작(`action`: ISSUE이면 화면이 API-04로 발급 확정, OPEN_GUIDE이면 사용법 안내), 빠른 답변 버튼(`quickReplies`), 추천 문구(`suggestions`), 횟수 차감 여부(`charged`), 번호 근거 안내(`basisNotice`), 유의 문구(`notice`), 오늘 남은 횟수(`remainingToday`) |
| API-09 | GET | `/api/statistics/summary` | 로또 통계 요약 조회 | 기간(`period`: 10, 50, 100, ALL 중 선택, 생략하면 100), 기준 회차(`basisRound`, 생략하면 최신 회차) | 번호 빈도, 장기 미출현, 홀짝, 고저, 합계, 구간, 연속수, 끝수, AC값, 소수 요약, 회차 통계 상태(준비 중·확정) |

AI 무료 횟수 규칙 (API-07, 08, 64 공통)
- 질문 1번 = AI 호출 1번 = 횟수 1회 차감. 근거 보기·다시 보기처럼 저장된 데이터를 보여주는 동작은 차감하지 않는다.
- AI 호출이 실패하면 차감한 횟수를 돌려준다(성공한 호출은 돌려주지 않는다). 막힌 시도(한도 초과 등)는 횟수를 쓰지 않는다.
- 기본 무료 횟수: 게스트 식별값 하루 5회, 접속지(IP) 하루 20회 (설정값). 한국 시간 0시에 초기화된다.
- 관리자는 횟수 제한을 적용하지 않는다 (관리자 로그인 구현 후 연결).
- 서비스 전체 일일 호출 한도·월 비용 한도는 기록(`ai_usage_log`)을 합산해서 판단한다.
- 무료 횟수는 서버 메모리에 저장하므로 서버를 다시 시작하면 초기화된다.
